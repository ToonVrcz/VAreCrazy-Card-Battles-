> **แผนเท่านั้น — ไม่มีการเปลี่ยน Production.** สถานะการ์ดมาจาก SELECT ของ Production ณ 2026-11-19. ผู้ที่กด Publish คือ Toon ผ่าน CMS Admin (ผมไม่ publish ให้).

## 1. Backup / PITR (ผลตรวจ)

| รายการ | ผล |
|---|---|
| Supabase project `varecrazy-card-battle` | ACTIVE_HEALTHY, region ap-southeast-1, Postgres 17 |
| แผนองค์กร | **Free** (`tier_free`) |
| PITR / backup อัตโนมัติ | **ไม่มีบนแผน Free** (PITR และ daily backup ที่กู้ได้ต้องเป็นแผนเสียเงิน; ผมตรวจจาก MCP ได้แค่ plan ไม่ใช่หน้า Backups — Toon ช่วยเปิด Dashboard → Database → Backups ยืนยันอีกครั้ง) |

**ข้อสรุป: ถือว่า "ไม่มี PITR"** → ต้องใช้ backup แบบกำหนดเอง (ไม่มีค่าใช้จ่ายเพิ่ม):
1. ก่อน apply migration: SELECT `cards`, `card_effects`, `card_versions` เก็บเป็นไฟล์ในเครื่อง (ข้อมูลการ์ดล้วน ไม่มีข้อมูลผู้เล่น). สถานะก่อน 024 ของ 33 ใบ = seed ที่ `5b85f89` (guard ของ 024 อิงค่านี้) จึงย้อนกลับได้ด้วย `024.down.sql`.
2. ผู้เล่น/ตาราง wallet/ledger/pvp: 019/018/021/022/023 ไม่แตะ — แต่ **ก่อน deploy ให้ export ตารางเหล่านี้ด้วย** (`players`, `wallets`, ledger, `pvp_matches`) เพื่อกู้กรณีโค้ดรางวัล F-03 ผิดพลาด (21 โปรไฟล์ — ขนาดเล็ก).
3. (ทางเลือก) `pg_dump` ผ่านเครื่องที่มี connection string (Toon เป็นคนใช้; ผมไม่แตะ secret).

**ผลต่อ Gate:** ข้อ "ยืนยัน Backup/PITR" = **ยืนยันแล้วว่าไม่มี PITR** → Gate ผ่านได้เมื่อมีไฟล์ snapshot ตามข้อ 1–2 ครบเท่านั้น.

## 3. ตรวจก่อน publish แต่ละใบ

1. แถวเอฟเฟกต์ไม่แสดง "ไม่ทำงาน" (ตรวจด้วยคอลัมน์ ✅ ด้านล่าง, ทำใน seed แล้ว: 55/55 parse ได้).
2. HP/ATK/DEF ตรงตาราง (HP/ATK ต้องเท่าเดิมทุกใบ).
3. ข้อความ/รูป/ธาตุครบ (ตรวจ Production แล้ว: ไม่มีใบไหนขาดรูปหรือธาตุ).
4. ผ่านด่าน publish ใน Admin (ถ้าเตือนให้ดูข้อความ ไม่ข้าม).
5. หลังแต่ละ Wave: เปิดเกมกับบอท 1 ครั้ง + ตรวจ `cards` ใน Admin ว่าเป็น published.

หมายเหตุ: การ publish จะสร้าง snapshot ใน `card_versions` ด้วยค่าที่ถูกต้องหลัง 024 (จึงควร apply 024 **ก่อน** publish เพื่อให้ประวัติเวอร์ชันถูกต้อง).
